# 문서 서식 지침 (docx · 한글 hwp/hwpx) — 로컬 에이전트용

- 작성일: 2026-10-09
- 근거: 「정보처리기사 실기 복원문제 모음(2020-2026)」을 한글(hwpx/hwp)로 옮기면서 사용자와 한 줄씩 맞춘 서식. 같은 서식을 앞으로 docx와 한글 문서에 계속 적용하기 위해 정리했다.
- 이 문서 안의 표시: **[확인]** = 코드나 파일을 직접 열어 확인한 사실, **[추정]** = 근거는 있으나 실제 한글(한컴오피스)에서 확인하지 못한 해석.
- 이 문서만 읽어도 작업을 이어갈 수 있게 썼다. 전체 구현은 부록 A(한글)·부록 B(docx)에 넣었다. 같은 이름의 스크립트(`build_hwpx.py`, `verify_hwpx.py`)가 프로젝트 폴더에 있으면 그것을 재사용하고, 없으면 부록 코드와 이 문서의 규칙으로 다시 만든다.

## 0. 먼저 읽을 것: 지켜야 할 것 요약

사용자가 docx 또는 한글(hwp, hwpx) 문서를 요청하면 아래를 기본값으로 쓴다. 사용자가 직접 지정한 서식이 있으면 그것이 우선이다.

1. 글꼴: 한글·영문 모두 **함초롬돋움**. 코드의 영문·숫자·기호만 **Courier New**.
2. 줄 간격 **130%**, 본문 **10pt**, 문제 번호 **11pt, 검정, 굵게**(파란색 쓰지 않기).
3. 문제처럼 한 덩어리인 내용은 **쪽 사이에서 쪼개지지 않게**. 한 쪽에 안 들어가면 그 문제를 통째로 새 쪽으로.
4. 빈 줄(줄바꿈 한 번)을 **문제 번호와 본문 사이 / 본문과 정답 사이 / 문제 구분선 위 / 구분선 아래**에 정확히 한 줄씩.
5. 표·그림·상자는 **담긴 칸의 안쪽 폭보다 좁게**(오른쪽이 잘리지 않게).
6. 코드는 **회색 상자**: 안쪽 여백 상하좌우 **3mm**, 가로폭은 **코드의 가장 긴 줄에 맞춤**(칸 폭 전체로 늘리지 않기).
7. 한글(hwp/hwpx)은 **실제 한글에서 열어 보지 못한다**(클라우드/리눅스 환경). 쪽 나눔은 추정값이고, `.hwpx`가 `.hwp`보다 더 검증된 경로다. 사용자에게 이 한계를 반드시 알린다.
8. 만든 뒤 **스스로 검증**한다(§10). 검증 스크립트가 통과하는 것만으로 "한글에서 잘 보인다"고 말하지 않는다.

## 4. 문제 단위의 구성 (위에서 아래로)

```
문제 번호 줄     "2020-1 문제 6 (SQL)"  11pt 검정 굵게
(빈 줄 한 줄)
문제 본문        보기·표·그림·코드 순서대로
(빈 줄 한 줄)
정답:            라벨은 굵게
해설:            있을 때만
(빈 줄 한 줄)
구분선           가는 회색 선
(빈 줄 한 줄)
다음 문제
```

- 빈 줄은 **진짜 빈 문단**이다(10pt, 130%). 사용자가 "줄바꿈 한 번"이라고 했으므로 줄 높이만큼만 벌어지게 한다.
- 빈 줄 앞 문단의 "뒤 간격"은 0으로 줄인다. 아니면 문단 간격 + 빈 줄이 겹쳐 두 줄 가까이 벌어진다.
- **예외(중요)**: 다음 문제가 "새 쪽에서 시작"하는 문제이면 구분선 아래 빈 줄을 넣지 않는다. 앞 문제가 쪽 끝까지 차 있으면 빈 줄이 다음 쪽으로 넘어가고, 거기에 쪽 나눔이 겹쳐 **내용 없는 쪽**이 생긴다. 회차(큰 제목) 마지막 문제 뒤에도 넣지 않는다(큰 제목이 쪽 나눔으로 시작하므로 같은 이유).
- 표 아래에 빈 줄을 넣을 때: 표와 표 사이에는 어차피 문단이 있어야 하므로(docx는 표 둘이 붙으면 합쳐진다) 이 빈 문단이 "구분선 아래 빈 줄"을 겸한다.

## 5. 문제가 쪽 사이에서 잘리지 않게

사용자 요구: "페이지 넘어가며 문제가 분리되어 잘리지 않게, 공간이 부족하면 그냥 그 문제를 통째로 새 페이지로."

### 5.1 왜 "다음 문단과 함께"(keepWithNext) 연쇄를 쓰지 않는가 [확인]
문제를 이루는 모든 문단에 keepWithNext를 줄줄이 거는 방식을 먼저 시도했는데, 라이브러리의 쪽 배치 추정기(estimate_pages)에서 **번호 줄만 앞 쪽에 남고 나머지가 다음 쪽으로 가는** 경우가 나왔다(2020-1 문제 19). 추정기는 이 속성을 한 단계씩만 따르고 연쇄로 따르지 않는다. 실제 한글이 어떻게 하는지는 확인하지 못했으므로 믿을 수 없는 방식으로 본다.

### 5.2 한글(HWPX)의 방식 [확인: 구조·추정기 / 추정: 실제 한글 동작]
**문제 전체를 "글자처럼 취급"하는 투명한 1칸 표 안에 넣는다.** 한글은 글자처럼 취급한 표를 쪽 경계에서 나누지 않고 통째로 다음 쪽으로 보낸다(python-hwpx 문서 "알려진 함정" 항목, 한컴에서 확인된 동작으로 설명되어 있다). 단, 같은 문서에 **쪽 본문보다 높은 표는 한 쪽에 그려지고 종이 아래 끝을 넘는 부분은 그려지지 않는다**고 적혀 있으므로 높이를 제한한다(이 환경에서 직접 확인하지는 못했다 [추정]).

2단계로 만든다.
1. **측정**: 모든 문제를 "새 쪽에서 시작"하는 임시 문서로 만들고 `estimate_pages`로 문제별 높이를 잰다. 높이 = (마지막 줄 쪽 − 첫 줄 쪽) × 본문 높이 + 마지막 줄 위치 + 1100(여유).
2. **배치**: 높이가 본문의 **80% 이하**면 1칸 표에 담는다(`wrap`). 80%~100%이면 표 없이 **새 쪽에서 시작**(`flat`, 번호 줄에 pageBreakBefore, 문단은 keepWithNext). **100% 초과**이면 새 쪽에서 시작하고(`flow`) 코드 상자를 "글자처럼 취급" 해제해 쪽 끝에서 줄 사이로 나뉘게 한다. 두 쪽에 걸칠 수밖에 없다고 사용자에게 알린다.

임계값을 85%가 아니라 80%로 쓴 이유: 추정기 오차가 17% 넘게 클 때만 표가 잘리는데, 한 문제를 새 쪽으로 보내는 비용이 작아서 여유를 더 두었다. (실제 420문제 중 표에 담은 문제 411개, 새 쪽에서 시작 9개 — 그중 한 쪽 초과 1개 [확인])

바깥 표 속성: 폭 = 본문 폭, 칸 안여백 좌우 0·위 100·아래 0, **표의 기본 안여백(inMargin)도 0**(§6), pageBreak=CELL, repeatHeader=0, 아래쪽 테두리만 회색 실선. 문제 번호 줄은 칸의 첫 문단.

### 5.3 docx의 방식 [확인: 시제품을 LibreOffice로 PDF 변환해 확인]
문제 전체를 1칸 표에 담고 **표 행에 `cantSplit: true`**를 준다. Word는 이 행을 쪽 사이에서 쪼개지 않고 통째로 다음 쪽으로 옮긴다. 시제품(부록 B)으로 40문제를 만들어 PDF로 바꿔 쪽별로 확인했을 때, 번호 줄 수와 "정답:" 줄 수가 모든 쪽에서 같았다(쪼개진 문제 0개). 한 쪽보다 큰 행은 쪼개질 수밖에 없다.

## 6. 표·그림이 칸 밖으로 잘리지 않게

### 원인 [확인: 수치 / 추정: 한글의 계산 방식]
처음에는 문제 칸(폭 48190) 안에 표·상자를 같은 폭(48190)으로 만들었다. 한글은 표의 **기본 안여백(inMargin, 기본 좌우 510씩)**을 칸 폭에서 빼는 것으로 보인다. 그러면 칸의 쓸 수 있는 폭은 47170이라 표·상자가 1020(3.6mm) 넘쳐 오른쪽이 잘린다. 처음 만든 파일을 다시 검사하니 이렇게 넘치는 표·상자가 171개였다.

### 규칙
- 문제 칸 안의 표·상자·코드 상자는 칸 폭보다 **3mm 좁게**(HWPUNIT 48190 → 최대 47340).
- 그림은 담기는 상자의 안쪽 폭보다 **2mm 더 좁게**, 가로 최대 560px·세로 최대 400px(96dpi 기준, 1px = 75 HWPUNIT). 원본이 2배 해상도 PNG이면 0.5배로.
- 바깥 문제 표의 inMargin은 0. **모든 표에서 표의 inMargin을 칸의 cellMargin과 같은 값으로 맞춘다**(어느 쪽을 따르는 프로그램에서도 같은 폭이 나오도록).
- 표 칸 안의 글은 **글자 단위 줄바꿈**(breakLatinWord=BREAK_WORD)으로. 칸보다 긴 영문 낱말이 칸 밖으로 나가 잘리지 않게 한다.
- 표 열 폭: 글자 수 기준(한글·전각 2, 그 밖 1, 한 단위 6.2pt + 좌우 여백 합 1100)으로 자연 폭을 구하고, 한도(위의 3mm 좁은 폭)를 넘으면 열 폭에 비례해 줄인다.
- docx: 표 `width`와 `columnWidths`를 DXA로 맞추고(둘의 합 일치), 칸 안의 표는 본문 폭 − 170(3mm) 이하로.

## 7. 코드 상자

- 코드 한 줄이 한 문단. **1칸짜리 회색(#F2F2F2) 표** 안에 넣는다.
- **안쪽 여백 상하좌우 3mm**(HWPUNIT 850 / DXA 170). 셀 안여백과 표 inMargin을 같은 값으로.
- **가로폭 = 가장 긴 줄의 폭 + 좌우 여백 3mm×2 + 약 1.4mm.** 줄 폭 추정: ASCII 글자 0.6em(Courier New의 글자 폭), 그 밖 글자는 1em(10pt에서 1000 HWPUNIT)으로 넉넉하게. 칸 폭 전체로 늘리지 않는다.
- 왼쪽 들여쓰기 기본 5mm. 그 때문에 줄이 꺾이면 들여쓰기를 줄인다. 그래도 최대 폭을 넘는 줄은 글자 단위로 상자 안에서 꺾이게 둔다(실제 사례: 97자 분량 1개).
- 코드 줄 문단은 글자 단위 줄바꿈(breakLatinWord·breakNonLatinWord=BREAK_WORD).
- 한 쪽보다 큰 문제에서는 코드 상자의 "글자처럼 취급"을 해제해 쪽 끝에서 나뉘게 한다(§5.2의 `flow`).

## 8. 한글(HWPX/HWP) 제작 레시피 (python-hwpx 6.8.0, Apache-2.0)

### 8.1 설치·저장·열기
```bash
pip install --break-system-packages python-hwpx
```
```python
from hwpx import HwpxDocument
doc = HwpxDocument.new()
doc.save_to_path("out.hwpx")      # HWPX
doc.save_to_path("out.hwp")       # HWP 5.0 (확장자로 형식이 정해진다)
d2 = HwpxDocument.open("out.hwp")  # .hwp 도 HwpxDocument.open 으로 읽는다 (HwpxPackage.open 은 hwpx 전용)
```

### 8.2 쓰는 API (부록 A에 전체 코드)
- 용지·여백: `doc.page.setup(paper_size="A4", orientation="PORTRAIT", margin_left_mm=20, margin_right_mm=20, margin_top_mm=15, margin_bottom_mm=15, header_margin_mm=10, footer_margin_mm=10, gutter_mm=0)`
- 머리글·쪽 번호: `doc.page.set_header(text=...)`, `doc.page.set_page_number(target="footer", align="CENTER", position="BOTTOM_CENTER")`, 만든 뒤 해당 문단의 서식을 9pt·맞춤으로 바꾼다.
- 글자 모양: `doc.styles.ensure_run(size=10, bold=..., base_char_pr_id="1")`. 글꼴 추가: `hdr.ensure_font("Courier New", lang="LATIN")` 후 charPr를 복제해 latin 글꼴만 그 id로.
- 문단 모양: `hdr.ensure_paragraph_format(base_para_pr_id="0", alignment=..., line_spacing_percent=130, margins={"left","intent","prev","next"}, break_setting={...}, border=...)`
- 표: 앵커 문단 `doc.add_paragraph("", para_pr_id_ref=..., include_run=False, inherit_style=False)` → `anchor.add_table(r, c, width=, height=, border_fill_id_ref=...)`, `tbl.set_column_widths([...])`. 칸 안 문단은 셀의 `subList`에 `hp:p`를 직접 넣는다(`_default_cell_paragraph_attributes()`).
- 그림: `doc.media.add_image(bytes, "png")` → `anchor.add_picture(id, width=, height=)`. 같은 파일은 한 번만 등록해 재사용.
- 기본 틀 정리: 모든 `charPr`의 `fontRef`를 0(함초롬돋움)으로, 모든 `lineSpacing`을 `PERCENT 130`으로(부록 A의 `_normalize_template`).

### 8.3 함정 [확인]
- **새 문서의 첫 문단은 구역 설정이 든 빈 문단**이다. `add_paragraph`는 그 뒤에 붙는다.
- **머리글·꼬리말이 .hwpx 안에 2개씩** 보인다(구역 설정 안에 한 번, 컨트롤 안에 한 번). 라이브러리가 그렇게 쓴다. `.hwp`로 다시 읽으면 1개씩이다. 검증할 때 머리글·꼬리말 문단은 따로 센다.
- 한 런(run)의 `itertext()`에는 그 안에 든 머리글 글자까지 섞인다. 서식 비교에서는 **런 바로 아래의 `hp:t`** 글자만 쓴다.
- 쪽 번호는 숫자 앞뒤에 "-"가 붙은 모양일 것이다(`hp:pageNum`의 sideChar="-", [추정]). 다르게 하려면 `hp:pageNum`/`autoNum`의 속성을 바꾼다.
- 표 안에 표(중첩)도 라이브러리가 지원한다(support-matrix "표 생성(병합·중첩 포함)": Create·Render-verified).
- **글자처럼 취급한 표는 쪽에서 나뉘지 않고, 쪽 본문보다 높으면 잘린다**(라이브러리 문서 "알려진 함정"). 높이를 제한한다.
- `.hwp` 쓰기는 라이브러리 문서 상 "Parse·Create"(생성 가능) 등급이고 "Render-verified"(실제 한컴 렌더 검증) 표시가 없다. `.hwpx`가 더 검증된 경로다.

### 8.4 .hwp는 보조 형식
두 형식 모두 만들어 전달하되 `.hwpx`를 먼저 열어 보라고 안내한다. 사용자가 한 번 "파일이 깨진 것 같다, 열리지 않는다"고 했다가 이후 서식 수정을 이어서 요청했으므로 열린 것으로 보이지만(추정), 어느 파일이 안 열렸는지·오류 메시지는 확인하지 못했다. 같은 보고가 오면 **어느 파일(.hwpx/.hwp)인지, 한글 버전, 오류 메시지 전문**을 먼저 묻는다.

## 9. docx 제작 레시피 (docx-js, 부록 B에 시제품 전체)

- `docx` npm 패키지(사전 설치됨). 글꼴: `{ ascii, hAnsi, eastAsia, cs }` 모두 함초롬돋움, 코드는 `ascii/hAnsi/cs`만 Courier New, `eastAsia`는 함초롬돋움.
- 기본 스타일에 줄 간격 `{ line: 312, lineRule: "auto", before: 0, after: 0 }`, 글자 크기 20(10pt), 문제 번호 22(11pt) 굵게, 글자색 `000000`.
- 문제 하나 = 1칸 표(폭 9638 DXA, `columnWidths: [9638]`, 셀 안여백 0, `cantSplit: true`, 아래쪽 테두리만 `BFBFBF`).
- 코드 상자 = 칸 안의 1칸 표(`ShadingType.CLEAR`, fill `F2F2F2`, 셀 `margins` 사방 170, 폭은 §7의 식, 테두리 없음). `ShadingType.SOLID`는 쓰지 않는다(검게 나온다).
- 표 폭은 `width`와 `columnWidths` 모두 DXA로, `WidthType.PERCENTAGE`는 쓰지 않는다(Google Docs에서 깨진다).
- 표 두 개 사이에는 반드시 문단을 둔다(붙으면 하나로 합쳐진다). 그 문단이 구분선 아래 빈 줄이다.
- 머리글·쪽 번호: `Header`, `Footer`와 `PageNumber.CURRENT`.
- 확인 [확인]: `soffice --headless --convert-to pdf proto.docx` → `pdftotext -f N -l N -layout` 로 쪽별 텍스트를 읽어 문제 번호 줄 수 = "정답:" 줄 수인지 센다. 이 환경에는 함초롬돋움이 없어 **대체 글꼴로 그려지므로** 폭·쪽 수는 근사값이다.

## 10. 검증 절차

한글(hwpx, hwp) — 한컴오피스가 없는 환경에서 할 수 있는 것 [확인]:
1. `validate_editor_open_safety(bytes)` 통과(`reopen_ok=True`, 오류 0, 문서 검증 이슈 0). 압축 파일 무결성(`unzip -t`), 글꼴·스타일·테두리 참조 번호 누락 없음, header.xml의 항목 개수(itemCnt) 불일치 없음. (참조 번호 `4294967295`는 번호 매기기 정의의 "없음" 표시라 정상이다.)
2. **서식 감사**: 모든 문단의 줄 간격 PERCENT 130, 글자색 #000000, 한글 글꼴 함초롬돋움, 영문 글꼴은 함초롬돋움 또는 Courier New. 글자 크기 분포가 9/10/11/15/22 외에 없는지.
3. **빈 줄 점검**: 문제마다 ①번호 뒤 ②정답 앞 ③구분선 위 ④구분선 아래(새 쪽 시작 문제 앞·회차 끝은 없음)에 빈 줄이 정확히 한 줄, 연달아 두 줄 이상 없음.
4. **폭 점검**: 모든 표·그림이 담긴 칸의 안쪽 폭(셀 폭 − max(cellMargin 합, inMargin 합) − 문단 왼쪽 여백)보다 **3mm 이상** 좁음. 코드 상자 안여백이 사방 850이고 폭이 가장 긴 줄에 맞는지.
5. **쪽 점검**: `estimate_pages`로 문제가 쪽 경계에 걸치는지, 표에 담은 문제 높이가 본문의 90% 이하인지, 새 쪽 시작 문제가 쪽 맨 위(vertpos 0)에서 시작하는지, 내용 없는 쪽이 없는지. 한 쪽보다 큰 문제는 예외 목록으로 명시.
6. **원본 대조**: 문항 수, 정답·해설 텍스트, 그림 수. 이전 docx와 본문 글자를 공백·목차 머리표를 무시하고 비교(이번에는 103,540자 전부 일치).
7. **.hwp 재열기**: `HwpxDocument.open("x.hwp")`로 다시 열어 .hwpx와 문단·표·그림 수, 글자 서식, 머리글·쪽 번호가 같은지.
8. **검사가 헛돌지 않는지 확인**: 규칙을 어긴 이전 버전 파일에 같은 검사를 돌려 **실패하는지** 본다(빈 줄이 없던 이전 파일에서 빈 줄 검사는 ①~③이 각 307곳·④가 399곳 실패했고, 폭 검사는 171곳 실패했다).

docx — 위 2~4번에 해당하는 항목을 XML이나 python-docx로 확인하고, PDF로 바꿔 쪽별로 눈으로 본다(`pdftoppm -r 60 -png`로 이미지로 만들어 열어 본다).

## 11. 사용자에게 알릴 것과 보고 방식

- **반드시 알릴 한계**: 실제 한글에서 열어 보지 못했다 / 쪽 나눔은 추정값이다 / `.hwp`는 `.hwpx`보다 덜 검증됐다 / 함초롬돋움은 한컴오피스 글꼴이라 파일에 내장되지 않는다 / (docx) 이 환경에서는 대체 글꼴로 확인했다.
- **확인된 사실과 추정을 구분**해서 쓴다. "한글에서 잘 보인다"고 말하지 않는다. 말할 수 있는 것은 "구조 검사·추정기·원본 대조를 통과했다"까지다.
- 사용자가 정하지 않아 내가 정한 값(제목 크기, 여백 등)은 보고에 적는다.
- 사용자 공통 선호(이 사용자의 stated 선호): 모든 답은 한국어. 아첨·칭찬 금지(질문이 실무적으로 영양가가 있을 때만 그 점을 짧게). 프로그래밍·알고리즘 설명은 비전공자 눈높이로 "왜"와 "어떻게"를 먼저, 기초 개념부터. 영어·전문 용어는 풀이하고 답변 맨 아래에 **"공식적인 정의"**와 **"비전공자용 용어 풀이"**를 나눠 붙인다. 에러 메시지는 해결책보다 **먼저 풀이**하고 원인과 해결을 분리한다. 참고한 공식 문서·URL을 출처로 남긴다. 논문은 "내가 어떻게 써먹을 수 있는가"를 포함한다.

## 12. 겪은 문제와 교훈 (같은 실수를 반복하지 않기 위해)

1. **keepWithNext 연쇄는 믿을 수 없었다**: 번호 줄만 앞 쪽에 남음(추정기 기준) → 1칸 표 방식으로 교체(§5).
2. **칸 폭과 같은 폭의 표·상자는 오른쪽이 잘렸다**: 원인은 표 inMargin(§6). 이전 파일에서 171개 넘침을 수치로 확인한 뒤 3mm 여유와 inMargin 정렬로 해결.
3. **구분선 아래 빈 줄이 쪽 끝에서 다음 쪽으로 넘어가 빈 쪽이 생길 위험**: 다음 문제가 새 쪽 시작이면 빈 줄을 넣지 않는 규칙으로 해결(§4). 그래도 "쪽 맨 위에 빈 줄 한 줄이 올라오는 쪽"이 최종본(추정 212쪽)에서 5곳 남았다(허용, 내용 없는 쪽은 0).
4. **한 쪽보다 큰 문제 1개(2024-1 문제 11, 코드 46줄)**: 빈 줄과 코드 상자 안여백을 넣고 나니 한 쪽을 약 3% 넘었다. `flow` 모드(새 쪽 시작 + 코드 상자 쪽 끝에서 나뉨)로 처리.
5. **머리글·꼬리말이 hwpx에서 2개씩**: 라이브러리가 그렇게 쓴다. hwp 재열기 비교에서 문단 수가 2개 다르게 나와 헤맸다 → 머리글·꼬리말은 따로 센다.
6. **런 서식 비교에서 1곳이 다르게 나온 것은 비교 코드의 허점**이었다(런의 itertext에 머리글 글자가 섞임). 비교 코드도 틀릴 수 있으니 차이가 나오면 코드 쪽부터 의심해 본다.
7. **`.hwp`는 라이브러리 문서상 렌더 검증 표시가 없다**: 사용자가 한 번 "열리지 않는다"고 보고했다(원인 미확인). `.hwpx` 우선.
8. **검사 기준을 처음에는 느슨하게 잡았다**: 이전 버전에 같은 검사를 돌려 실패하는 것을 확인하는 단계(§10-8)를 습관으로.

### A-2. 서식 묶음 (글꼴·줄 간격·문단 모양)

```python
class Styles:
    """charPr / paraPr / borderFill 을 한 번만 만들어 두고 이름으로 꺼낸다."""

    def __init__(self, doc):
        self.doc = doc
        self.hdr = doc.oxml.headers[0]
        self._para = {}
        self._normalize_template()
        self.courier = self.hdr.ensure_font("Courier New", lang="LATIN")
        # --- 글자 모양 (모두 검정)
        self.c_body = self._run(size=10)
        self.c_bold = self._run(size=10, bold=True)
        self.c_italic = self._run(size=10, italic=True)
        self.c_qnum = self._run(size=11, bold=True)           # 문제 번호: 11pt, 검정, 굵게
        self.c_title = self._run(size=22, bold=True)
        self.c_sub = self._run(size=14)
        self.c_h1 = self._run(size=15, bold=True)
        self.c_small = self._run(size=9)
        self.c_sep = self._run(size=2)
        self.c_code = self._code_run(size=10)
        # --- 테두리/바탕
        self.bf_code = doc.styles.ensure_border_fill(border_color="#F2F2F2", border_width="0.12 mm", fill_color="#F2F2F2")
        self.bf_sep = doc.styles.ensure_border_fill(border_color="#BFBFBF", border_width="0.12 mm", active_borders=["bottom"])
        self.bf_table = doc.styles.ensure_border_fill(border_color="#555555", border_width="0.15 mm")
        self.bf_box = doc.styles.ensure_border_fill(border_color="#333333", border_width="0.25 mm")
        self.bf_head = self.hdr.ensure_shading_border_fill("#EDEFF2", base_border_fill_id=self.bf_table)
        self.bf_outer = self.bf_sep           # 문제 전체를 담는 표: 아래쪽 가는 회색 줄만 (문제 사이 구분선)

    # ---- 기본 틀(template)의 글꼴을 모두 함초롬돋움으로, 기본 줄간격을 130%로
    def _normalize_template(self):
        for cp in self.hdr.element.iter(HH + "charPr"):
            fr = cp.find(HH + "fontRef")
            for k in ("hangul", "latin", "hanja", "japanese", "other", "symbol", "user"):
                fr.set(k, "0")
        for ls in self.hdr.element.iter(HH + "lineSpacing"):
            ls.set("type", "PERCENT")
            ls.set("value", "130")
            ls.set("unit", "HWPUNIT")

    def _run(self, size, bold=False, italic=False):
        return self.doc.styles.ensure_run(size=size, bold=bold or None, italic=italic or None, base_char_pr_id="1")

    def _code_run(self, size):
        """영문·숫자·기호(LATIN 칸)만 Courier New, 한글·한자·기타는 함초롬돋움"""
        cid = self.doc.styles.ensure_run(size=size, base_char_pr_id="1")
        base = [e for e in self.hdr.element.iter(HH + "charPr") if e.get("id") == cid][0]

        def modifier(cp):
            cp.set("height", base.get("height"))
            cp.find(HH + "fontRef").set("latin", self.courier)

        el = self.hdr.ensure_char_property(
            predicate=lambda e: (e.find(HH + "fontRef").get("latin") == self.courier
                                 and e.get("height") == base.get("height")),
            modifier=modifier, base_char_pr_id=cid)
        return el.get("id")

    # ---- 문단 모양
    def para(self, align="JUSTIFY", left=0, indent=0, prev=0, nxt=0, keep=True, keep_lines=True,
             page_break=False, border=None, code=False):
        key = (align, left, indent, prev, nxt, keep, keep_lines, page_break, border, code)
        if key in self._para:
            return self._para[key]
        brd = None
        if border == "code":
            brd = {"borderFillIDRef": self.bf_code, "offsetLeft": 200, "offsetRight": 200,
                   "offsetTop": 0, "offsetBottom": 0, "connect": "1", "ignoreMargin": "0"}
        elif border == "sep":
            brd = {"borderFillIDRef": self.bf_sep, "offsetLeft": 0, "offsetRight": 0,
                   "offsetTop": 0, "offsetBottom": 0, "connect": "0", "ignoreMargin": "0"}
        pid = self.hdr.ensure_paragraph_format(
            base_para_pr_id="0", alignment=align, line_spacing_percent=130,
            margins={"left": left, "intent": indent, "prev": prev, "next": nxt},
            break_setting={"keep_with_next": keep, "keep_lines": keep_lines,
                           "page_break_before": page_break, "widow_orphan": False},
            border=brd)
        if code:        # 코드 줄은 글자 단위로 줄바꿈(긴 식별자도 여백에서 꺾이게)
            pe = [e for e in self.hdr.element.iter(HH + "paraPr") if e.get("id") == pid][0]
            bs = pe.find(HH + "breakSetting")
            bs.set("breakLatinWord", "BREAK_WORD")
            bs.set("breakNonLatinWord", "BREAK_WORD")
        self._para[key] = pid
        return pid

    def with_gap(self, pid, prev=None, nxt=None):
        """같은 모양에서 문단 앞/뒤 간격만 바꾼 문단 모양 번호 (st.para 로 만든 모양만 가능)"""
        pid = str(pid)
        for key, v in list(self._para.items()):
            if str(v) == pid:
                align, left, indent, p0, n0, keep, keep_lines, page_break, border, code = key
                return self.para(align=align, left=left, indent=indent,
                                 prev=p0 if prev is None else prev, nxt=n0 if nxt is None else nxt,
                                 keep=keep, keep_lines=keep_lines, page_break=page_break, border=border, code=code)
        return None
```

### A-3. 문단·표를 놓는 곳(본문과 표 칸을 같은 코드로) 

```python
class Sink:
    """문단과 표를 놓는 곳. 본문(BodySink)이거나 표 칸 안(CellSink)이다. keep 은 '다음 문단과 함께' 사용 여부."""

    def __init__(self, st, keep):
        self.st = st
        self.keep = keep

    def para(self, runs, pid):
        p = self.anchor(pid)
        for text, cid in runs:
            p.add_run(text, char_pr_id_ref=cid)
        if not runs:
            p.add_run("", char_pr_id_ref=self.st.c_body)
        return p

    def anchor(self, pid, with_run=False):      # 표·그림을 붙일 빈 문단
        raise NotImplementedError

    def last_p(self):
        """이 곳의 마지막 최상위 문단(lxml 요소)"""
        raise NotImplementedError

    def tighten_last(self, nxt=0):
        """마지막 문단 뒤 간격을 줄인다(그 뒤에 진짜 빈 줄을 따로 넣을 때, 간격이 겹쳐 두 줄 넘게 벌어지지 않게)"""
        p = self.last_p()
        new = self.st.with_gap(p.get("paraPrIDRef"), nxt=nxt)
        if new is not None:
            p.set("paraPrIDRef", str(new))

    def blank(self, keep=None):
        """빈 줄 하나(= 줄바꿈 한 번): 본문 글자 크기·줄 간격 130% 의 빈 문단"""
        k = self.keep if keep is None else keep
        return self.para([("", self.st.c_body)], self.st.para(align="LEFT", prev=0, nxt=0, keep=k, keep_lines=False))


class BodySink(Sink):
    def __init__(self, doc, st, keep):
        super().__init__(st, keep)
        self.doc = doc
        self.in_cell = False

    def anchor(self, pid, with_run=False):
        return self.doc.add_paragraph("", para_pr_id_ref=pid, char_pr_id_ref=self.st.c_body,
                                      include_run=False, inherit_style=False)

    def last_p(self):
        sec = self.doc.sections[-1].element
        return [c for c in sec if c.tag == HP + "p"][-1]


class CellSink(Sink):
    def __init__(self, st, sub, section, doc):
        super().__init__(st, False)
        self.sub, self.section, self.doc = sub, section, doc
        self.in_cell = True

    def anchor(self, pid, with_run=False):
        from hwpx.oxml.paragraph import HwpxOxmlParagraph
        from hwpx.oxml._document_primitives import _default_cell_paragraph_attributes
        attrs = _default_cell_paragraph_attributes()
        attrs["paraPrIDRef"] = str(pid)
        p = self.sub.makeelement(HP + "p", attrs)
        self.sub.append(p)
        return HwpxOxmlParagraph(p, self.section)

    def last_p(self):
        return self.sub.findall(HP + "p")[-1]
```

```python
def clear_cell(cell):
    sub = cell.element.find(HP + "subList")
    for p in list(sub.findall(HP + "p")):
        sub.remove(p)
    return sub


def cell_margin(cell, left, right, top, bottom):
    cm = cell.element.find(HP + "cellMargin")
    for k, v in (("left", left), ("right", right), ("top", top), ("bottom", bottom)):
        cm.set(k, str(v))
    cell.element.set("hasMargin", "1")


def table_flags(tbl, repeat_header=False, page_break="CELL"):
    t = tbl.element
    t.set("pageBreak", page_break)
    t.set("repeatHeader", "1" if repeat_header else "0")


def table_inmargin(tbl, left, right, top, bottom):
    """표 전체의 기본 안여백. 칸마다 따로 정한 안여백(cellMargin)과 같은 값으로 맞춰 두어, 어느 쪽을 따르는 프로그램에서도 칸의 쓸 수 있는 폭이 같게 한다."""
    im = tbl.element.find(HP + "inMargin")
    for k, v in (("left", left), ("right", right), ("top", top), ("bottom", bottom)):
        im.set(k, str(v))


def code_text_width(line):
    """코드 한 줄의 폭(HWPUNIT, 10pt 기준). 영문·숫자·기호는 Courier New(글자 폭 0.6em), 그 밖은 1em 으로 넉넉히 센다."""
    return sum(600 if ord(ch) < 128 else 1000 for ch in line)


def v_align(cell, how="TOP"):
    cell.element.find(HP + "subList").set("vertAlign", how)
```

### A-5. 코드 상자

```python
    def code_block(self, sink, code):
        """코드: 글자 폭에 맞춘 회색 상자(1칸 표). 안쪽 여백은 상하좌우 3mm, 가로는 가장 긴 줄 + 약간."""
        st = self.st
        lines = clean(code).split("\n")
        want = max(code_text_width(ln) for ln in lines) + 2 * CODE_PAD + 400    # 가장 긴 줄 + 여백 3mm×2 + 약간(400 ≈ 1.4mm)
        indent = max(0, min(CODE_INDENT, AVAIL - want))            # 5mm 들여쓰기가 줄을 꺾이게 만들면 들여쓰기를 줄인다
        width = min(AVAIL - indent, want)
        anchor = sink.anchor(st.para(align="LEFT", left=indent, nxt=500, keep=sink.keep))
        tbl = anchor.add_table(1, 1, width=width, height=1800, border_fill_id_ref=st.bf_code,
                               char_pr_id_ref=st.c_code)
        table_flags(tbl, repeat_header=False, page_break="CELL")
        table_inmargin(tbl, CODE_PAD, CODE_PAD, CODE_PAD, CODE_PAD)
        cell = tbl.cell(0, 0)
        cell_margin(cell, CODE_PAD, CODE_PAD, CODE_PAD, CODE_PAD)
        v_align(cell, "TOP")
        if self.flow_code:
            tbl.set_treat_as_char(False)
        csink = CellSink(st, clear_cell(cell), anchor.section, self.doc)
        pid = st.para(align="LEFT", keep=False, code=True)        # 글자 단위 줄바꿈(상자보다 긴 줄은 상자 안에서 꺾인다)
        for line in lines:
            csink.para([(line, st.c_code)], pid)
        return tbl
```

```python
    def question(self, sink, r, q, F, E, C, new_page=False, top_gap=0):
        st = self.st
        key = f"{r['year']}-{r['round']}#{q['number']}"
        lang = "이론" if (not q.get("language") or q["language"] == "기타") else q["language"]
        diff = f" · 난이도 {q['difficulty']}" if q.get("difficulty") else ""
        # 문제 번호: 11pt, 검정, 굵게
        self.text(sink, f"{r['year']}-{r['round']} 문제 {q['number']} ({lang}{diff})", st.c_qnum,
                  st.para(align="LEFT", prev=top_gap, nxt=0, keep=sink.keep, page_break=new_page))
        sink.blank()                                   # 문제 번호 ↔ 문제 본문: 빈 줄 하나
        blocks = F.get(key)
        if blocks is None:
            raise RuntimeError("formatted prompt missing: " + key)
        self.prompt_blocks(sink, blocks)
        ct = C.get(key)
        code = (q.get("code") or "").rstrip("\n")
        if ct:
            self.data_table(sink, ct, header=True, caption=None)
        elif code.strip():
            self.code_block(sink, code)
        sink.tighten_last(0)
        sink.blank()                                   # 문제 본문 ↔ 정답: 빈 줄 하나
        self.answer(sink, q.get("answer") or "")
        expl = (q.get("explanation") or "").strip()
        if expl:
            self.explanation(sink, E.get(key) or [expl])
        sink.tighten_last(0)
        sink.blank()                                   # 구분선 바로 위: 빈 줄 하나
```

```python
def measure_heights(doc):
    """모든 문제가 새 쪽에서 시작하는 임시 문서에서 문제별 높이(HWPUNIT)를 잰다.
    문제가 한 쪽을 넘으면 (쪽 수 차이 × 본문 높이 + 마지막 줄 위치)로 계산한다."""
    from verify_hwpx import question_units
    est = estimate_pages(doc)
    if est.pages is None:
        raise RuntimeError("쪽 추정 불가: " + "; ".join(est.unsupported))
    top, groups = question_units(doc)
    heights = {}
    for g in groups:
        first = est.lines[g["start"]][0]
        last = est.lines[g["end"]][-1]
        assert first.vertpos == 0, (g["key"], first)       # 새 쪽에서 시작했는지(측정 전제)
        heights[g["key"]] = (last.page - first.page) * BODY_H + last.vertpos + 1100
    return heights
```

## 부록 B. docx 시제품 (docx-js, 쪽 나눔·코드 상자·빈 줄 확인용)

실행: `node proto_docx.js` → `proto.docx`, 이어서 `soffice --headless --convert-to pdf proto.docx`. 이 시제품은 문제집 데이터(`formatted_prompts.json`, `raw/*.json`)를 읽는다. 데이터 부분만 바꿔 쓰면 된다. [확인] 40문제 / 25쪽 / 쪽 경계에 걸린 문제 0개.

```javascript

const fs = require('fs');
const D = require('docx');
const { Document, Packer, Paragraph, TextRun, Table, TableRow, TableCell, WidthType, BorderStyle, ShadingType, AlignmentType, Footer, Header, PageNumber, TableLayoutType } = D;

const ROOT = '/home/claude/jcb_restored';
const F = JSON.parse(fs.readFileSync(`${ROOT}/formatted_prompts.json`, 'utf8'));
const mmTw = (mm) => Math.round(mm * 56.6929);       // mm -> DXA(twip)
const PAGE_W = 11906, PAGE_H = 16838;
const M_LR = mmTw(20), M_TB = mmTw(15), M_HF = mmTw(10);
const TEXT_W = PAGE_W - 2 * M_LR;                    // 9638
const SAFE = mmTw(3), AVAIL = TEXT_W - SAFE;         // 칸 안 표·상자의 최대 폭
const PAD = mmTw(3);                                 // 코드 상자 안여백 3mm = 170
const FONT = '함초롬돋움';
const FONT_RUN = { ascii: FONT, hAnsi: FONT, eastAsia: FONT, cs: FONT };
const CODE_RUN = { ascii: 'Courier New', hAnsi: 'Courier New', eastAsia: FONT, cs: 'Courier New' };
const LINE = { line: 312, lineRule: 'auto', before: 0, after: 0 };   // 130%

const run = (text, o = {}) => new TextRun({ text, font: o.code ? CODE_RUN : FONT_RUN, size: o.size || 20, bold: !!o.bold, color: '000000' });
const para = (children, o = {}) => new Paragraph({ children, spacing: LINE, alignment: o.align || AlignmentType.LEFT, indent: o.indent });
const blank = () => para([run('')]);
const textW = (s) => [...s].reduce((a, ch) => a + (ch.codePointAt(0) < 128 ? 0.6 : 1.0) * 10 * 20, 0);   // pt*20 = twip

const NONE = { style: BorderStyle.NONE, size: 0, color: 'FFFFFF' };
const noBorders = { top: NONE, bottom: NONE, left: NONE, right: NONE };

function codeBox(code) {
  const lines = code.replace(/\t/g, '    ').split('\n');
  const want = Math.max(...lines.map(textW)) + 2 * PAD + 80;          // 가장 긴 줄 + 안여백 3mm×2 + 약 1.4mm
  const indent = Math.max(0, Math.min(mmTw(5), AVAIL - want));
  const w = Math.min(AVAIL - indent, Math.round(want));
  return new Table({
    width: { size: w, type: WidthType.DXA }, columnWidths: [w], indent: { size: indent, type: WidthType.DXA },
    layout: TableLayoutType.FIXED,
    borders: { ...noBorders, insideHorizontal: NONE, insideVertical: NONE },
    rows: [new TableRow({ cantSplit: false, children: [new TableCell({
      width: { size: w, type: WidthType.DXA },
      shading: { type: ShadingType.CLEAR, fill: 'F2F2F2', color: 'auto' },
      margins: { top: PAD, bottom: PAD, left: PAD, right: PAD },
      borders: noBorders,
      children: lines.map((l) => para([run(l, { code: true })])),
    })] })],
  });
}

function question(key, q, code) {
  const [yr, rest] = key.split('-'); const [rd, no] = rest.split('#');
  const kids = [para([run(`${yr}-${rd} 문제 ${no} (${q.language || '이론'})`, { size: 22, bold: true })]), blank()];
  for (const b of F[key] || []) for (const t of b.lines || []) kids.push(para([run(t)]));
  if (code) { kids.push(codeBox(code)); }
  kids.push(blank(), para([run('정답:', { bold: true }), run(' ' + (q.answer || '').split('\n').join(' / '))]), blank());   // 구분선 바로 위 빈 줄
  // 문제 하나 = 1칸 표. 행을 쪼개지 않으므로 Word 는 이 행을 통째로 다음 쪽으로 옮긴다. 아래쪽 가는 회색 선이 문제 구분선.
  return new Table({
    width: { size: TEXT_W, type: WidthType.DXA }, columnWidths: [TEXT_W], layout: TableLayoutType.FIXED,
    borders: { ...noBorders, bottom: { style: BorderStyle.SINGLE, size: 4, color: 'BFBFBF' }, insideHorizontal: NONE, insideVertical: NONE },
    rows: [new TableRow({ cantSplit: true, children: [new TableCell({
      width: { size: TEXT_W, type: WidthType.DXA }, margins: { top: 0, bottom: 0, left: 0, right: 0 },
      borders: { ...noBorders, bottom: { style: BorderStyle.SINGLE, size: 4, color: 'BFBFBF' } },
      children: kids,
    })] })],
  });
}

const raw = {};
for (const f of fs.readdirSync(`${ROOT}/raw`)) {

  for (const q of r.questions) raw[`${r.year}-${r.round}#${q.number}`] = q;

const keys = Object.keys(F).filter((k) => raw[k] && k.startsWith('2023-')).slice(0, 40);
const body = [];
for (const k of keys) {

  body.push(question(k, q, (q.code || '').trimEnd()));

}
const doc = new Document({
  styles: { default: { document: { run: { font: FONT_RUN, size: 20 }, paragraph: { spacing: LINE } } } },
  sections: [{
    properties: { page: { size: { width: PAGE_W, height: PAGE_H }, margin: { top: M_TB, bottom: M_TB, left: M_LR, right: M_LR, header: M_HF, footer: M_HF } } },
    headers: { default: new Header({ children: [para([run('서식 시제품', { size: 18 })], { align: AlignmentType.RIGHT })] }) },
    footers: { default: new Footer({ children: [para([new TextRun({ children: [PageNumber.CURRENT], font: FONT_RUN, size: 18 })], { align: AlignmentType.CENTER })] }) },

Packer.toBuffer(doc).then((b) => { fs.writeFileSync('proto.docx', b); console.log('ok', keys.length, '문제'); });
```

## 부록 C. 용어 풀이 (사람이 읽는 용)

- **HWPX / HWP**: 한글 문서 파일 형식. HWPX는 XML 문서들을 ZIP으로 묶은 개방형 형식이고, HWP는 한글의 전통적인 이진 형식이다.
- **HWPUNIT**: 한글 문서의 길이 단위. 1/7200인치. 1pt = 100.
- **DXA(twip)**: Word 문서의 길이 단위. 1/1440인치. 1pt = 20.
- **글자처럼 취급**: 표·그림을 글자 한 개처럼 문단 안에 놓는 설정. 이 설정의 표는 쪽 사이에서 쪼개지지 않는다.
- **keepWithNext(다음 문단과 함께)**: 이 문단을 다음 문단과 같은 쪽에 두라는 설정. 문단이 길게 이어지면 효과가 불확실하다.
- **cantSplit(행 쪼개지 않기)**: Word 표 행이 쪽 경계에서 나뉘지 않게 하는 설정.
- **inMargin / cellMargin**: 표 전체의 기본 안여백 / 칸 하나의 안여백. 칸의 쓸 수 있는 폭에 영향을 준다.
- **estimate_pages**: python-hwpx의 쪽 배치 추정 함수. 한글 없이 각 줄이 몇 쪽 어디에 놓일지 계산하지만 근사값이다.
- **vertpos**: 한 줄이 그 쪽 본문 맨 위에서 아래로 얼마나 떨어져 있는지(HWPUNIT). 0이면 쪽 맨 위.
- **음성 대조(negative control)**: 검사가 실제로 잘못된 것을 잡아내는지 확인하려고, 규칙을 어긴 파일에 같은 검사를 돌려 실패하는지 보는 것.
