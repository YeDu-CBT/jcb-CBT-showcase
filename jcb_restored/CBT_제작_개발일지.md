# 정보처리기사 CBT 제작 에이전트 지침서 개발 일지

- **대상 문서**: `CBT_제작_에이전트_지침.md` (이하 **지침서**) — 보존된 15개 버전, v1.0 → v1.15
- **기간**: 2026-10-08 ~ 2026-10-12 (한국 시간. 지침서에 반영된 시각 기준)
- **협업 주체**: 사용자(요구·지적·결정) / Claude(AI 에이전트: 구현·검증·문서화)
- **작성**: 2026-10-13, Claude. 이 일지는 **AI가 보존된 기록을 읽고 다시 정리한 2차 기록**입니다(0.3 참고).

## 0. 이 일지를 읽는 법

### 0.1 지침서가 무엇인가

정보처리기사 실기 기출 복원문제(2020~2026, 21개 회차)를 웹에서 모아 **(1) 읽는 문서(MD·DOCX)** 와 **(2) CBT 모의고사 사이트**로 만드는 전 과정에서, 에이전트가 지켜야 할 규칙과 겪은 실수를 적어 둔 작업 설계도입니다. 다른 자격증에도 같은 품질로 적용하고, 새 세션의 에이전트가 이어받을 수 있게 하는 것이 목적입니다. 사용자가 다른 국가자격증도 웹에서 모아 같은 방식으로 만들 계획이라 제작 과정을 에이전트용 지침 .md로 요청한 것이 출발점입니다(사용자가 이전에 밝힌 내용을 적어 둔 기억 기록에서 확인 [사실]. 요청 당시의 문구는 [기록 없음]).

지침서는 한 번 쓰고 끝난 문서가 아닙니다. **사용자가 요구하거나 지적할 때마다, 그리고 에이전트가 실수하거나 새로 알게 될 때마다 갱신**되었습니다. 그래서 지침서의 버전 변화가 곧 협업의 기록입니다.

## 2. 처음부터 끝까지 바뀌지 않은 것 — 협업 약속 (지침서 2장)

2장은 v1.0과 v1.15가 같습니다 [사실: 26줄 비교]. 내용은 네 가지입니다.

| 영역 | 약속 |
|---|---|
| 소통 | 한국어. 아첨하지 않음(질문이 실무적으로 가치 있을 때만 그렇게 말함). 작업을 받으면 **첫 문장으로 무엇을 할지** 알림. 사용자가 한동안 소식을 못 들으면 "무엇을 하고 있는지 몇 단어로" 먼저 말함. 작업 목록의 마지막 항목은 "검증". 확인된 사실과 추정을 구분 |
| 설명 방식 | 비전공자 눈높이, **"왜"와 "어떻게"를 먼저**. 영어·전문용어는 풀이하고 답변 맨 아래에 "공식적인 정의"와 "비전공자용 용어 풀이"를 나눠 붙임. 에러 메시지는 해결책보다 **읽는 법 → 원인 → 해결** 순서. 참고한 공식 문서 URL을 남김 |
| 파일 취급 | 사용자 파일은 원본이므로 **복사본에서 작업**. 기존 산출물을 고치기 전에 `backup_before_<작업명>/`에 먼저 복사. 변환물(PDF 등)이 낡은 채 남지 않게 함 |
| 질문 규칙 | 요청이 명확하거나 다시 하기 쉬우면 **묻지 말고 시작**. 되돌리기 어렵고 해석이 갈리는 결정만 묻기. 사용자가 자리에 없으면 가장 합리적인 해석으로 진행하고 어떤 해석을 택했는지 맨 앞에 적기 |

[해석] 이 약속이 지침서 안에 적혀 있기 때문에, 대화가 끊기고 새 세션이 시작되어도 같은 방식의 협업이 재현됩니다. 이후의 모든 갱신은 이 틀 안에서 일어났습니다. 백업 폴더가 26개 쌓인 것은 "고치기 전에 먼저 복사"라는 약속이 지켜진 결과입니다 [사실: 폴더 수 / 해석: 원인].

관련 문서: 한글(HWPX)·DOCX 서식 규칙은 별도 문서 `문서_서식_에이전트_지침.md`(10-09 11:54 저장, 46,815바이트)에 있습니다. 그 문서는 "정보처리기사 복원문제 모음을 한글로 옮기면서 사용자와 한 줄씩 맞춘 서식"을 근거로 한다고 스스로 밝힙니다. 이 문서의 버전 사본은 보존되어 있지 않아 이 일지에서는 다루지 않습니다 [기록 없음].

## 8. 포트폴리오로 쓸 때의 주의

## 부록 D. 비전공자용 용어 풀이

- **지침서** — 요리 가게의 "조리 매뉴얼"에 해당합니다. 새로 온 직원(새 AI 세션)이 이 매뉴얼만 읽으면 같은 맛(품질)을 낼 수 있게, 그동안 있었던 사고와 손님(사용자)의 요청을 모두 적어 둔 책입니다.
- **버전 (v1.0, v1.15)** — 문서에 붙은 "몇 번째 수정본" 번호표입니다. 이 지침서에서는 의미 있는 수정이 있을 때 순서대로 올렸습니다.
- **백업 (backup)** — 고치기 전에 해 두는 복사본. 이 프로젝트에서는 작업을 시작할 때마다 `backup_before_작업이름` 폴더를 만들어 고치기 전 상태를 보관했고, 그 폴더들이 이 일지의 증거가 되었습니다.
- **해시(MD5)** — 파일의 "지문" 같은 짧은 값입니다. 두 파일의 지문이 같으면 내용이 같다고 봅니다. 이름이나 날짜가 달라도 내용이 같은지 가려낼 수 있어서 썼습니다.
- **diff** — 두 문서를 나란히 놓고 "여기가 달라졌다"를 자동으로 표시해 주는 비교입니다. 책의 개정판에서 바뀐 쪽만 찾는 일과 같습니다.
- **원본(raw)** — 가공하기 전의 날것 데이터. 문서와 사이트는 모두 여기서 다시 만들어지므로, 문서나 사이트를 직접 고치지 않고 원본만 고칩니다.
- **2차 대조** — 처음에 옮겨 적은 문제를, 원문 페이지를 다시 열어 한 문항씩 비교해 빠진 표·그림·보기를 찾는 작업입니다.
- **이미지 전용 문항** — 원문에서 문제가 글이 아니라 그림 파일로만 올라와 있어 처음에는 글로 옮기지 못한 문제. 나중에 표는 표로, 그림은 다시 그려서 되살렸습니다.
- **합치기(같은 문제 합치기)** — 여러 회차에 다시 나온 똑같은 문제를 화면에서는 한 번만 보이게 하고 나온 회차를 모두 적어 주는 일. 원본은 지우지 않습니다.
- **멱등성** — 계산기의 `=`를 몇 번 눌러도 같은 답이 나오는 것처럼, 같은 작업을 몇 번 돌려도 결과가 같게 만드는 설계입니다. 중복이 쌓이는 사고를 막습니다.
- **회귀 시험** — 새 기능을 넣은 뒤, 예전에 잘 되던 것이 망가지지 않았는지 처음부터 다시 눌러 보는 시험입니다. 집을 고친 뒤 수도·전기가 아직 되는지 확인하는 일과 같습니다.
- **자동 시험(Playwright)** — 사람 대신 컴퓨터가 브라우저를 열어 버튼을 누르고 결과를 확인해 주는 도구입니다. 이 프로젝트의 "항목 N개 통과"는 이런 확인 항목의 개수입니다.
- **모의 환경(mock)** — 진짜 서버나 로그인이 필요한 기능을 확인할 때 쓰는 "연습용 가짜 무대"입니다. 무대에서 잘 돼도 실제 무대에서 되는지는 따로 확인해야 하므로, 이 일지는 그런 부분을 [추정]으로 남겼습니다.
- **동기화** — 집 컴퓨터와 노트북의 풀이 기록·메모를 같은 내용으로 맞추는 일입니다.
- **localStorage** — 내 브라우저 안에 작은 메모를 남기는 공간. 풀이 기록은 파일이 아니라 여기에 있어서 다른 기기에 저절로 따라가지 않습니다.
- **폴더 연결** — 사용자가 폴더를 한 번 골라 주면, 그 폴더 안의 기록 파일을 사이트가 읽고 쓰게 하는 기능입니다. 웹 페이지가 마음대로 내 폴더를 뒤지지 못하도록 사용자가 직접 "허락"하는 구조입니다.
- **지움 표시(tombstone)** — "이건 몇 시에 지웠다"고 적어 둔 쪽지. 다른 기기에 남은 옛 기록이 합칠 때 다시 살아나지 않게 합니다.
- **서식 편집기 / 정화기** — 메모에 굵게·색·정렬 같은 꾸밈을 줄 수 있는 입력칸이 서식 편집기, 바깥에서 들어온 꾸밈 정보를 "허용한 것만 통과"시키는 거름망이 정화기입니다. 거름망이 없으면 악성 코드가 메모에 섞여 들어올 수 있습니다.
- **조합 입력(IME)** — "ㅎ → 하 → 한"처럼 키를 여러 번 눌러 한 글자를 완성하는 한글 입력 방식. 글자가 완성되기 전에 프로그램이 입력칸을 건드리면 글자가 깨질 수 있어 따로 대비했습니다.
- **버전 칩** — 사이트 맨 위에 붙은 `Ver 2.5 · 수정 21회` 같은 알약 모양의 작은 표시. 지금 보는 사이트가 몇 번째 수정본인지 알려 줍니다. (지침서의 `v1.N`은 지침서 번호이고, 사이트의 `Ver`는 사이트 번호로 서로 다릅니다.)
- **게시 / 재게시** — 만든 사이트를 링크로 열 수 있게 올리는 일, 같은 주소로 고쳐 다시 올리는 일. 재게시할 때마다 칩 숫자를 1씩 올렸습니다.
- **함정 모음** — 지침서 13장의 표. "이런 증상이 났다 → 원인은 이랬다 → 앞으로는 이렇게 막는다"를 한 줄씩 적은 실수 기록장입니다. 이 일지는 20줄에서 95줄로 늘어난 과정을 따라갑니다.
- **[사실] / [추정] / [해석] / [기록 없음]** — 이 일지의 신뢰도 표시입니다. 사실은 직접 확인, 추정은 근거는 있으나 미확인, 해석은 작성자(AI)의 풀이, 기록 없음은 남아 있는 자료가 없다는 뜻입니다.
